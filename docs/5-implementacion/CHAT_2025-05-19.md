# Contexto de Sesion — 19 Mayo 2026

## Resumen

Sesion de implementacion de 3 modulos principales:

1. **Integracion SoilGrids API** — Consulta automatica de datos de suelo desde ISRIC
2. **Random Forest en Produccion** — El modelo ML entrenado ahora se usa en lugar del heuristico
3. **Migracion DB a Local (PostGIS en Docker)** — Reemplazo de Supabase DB por local

---

## 1. SoilGrids API

### Archivos creados

- `backend/app/services/soil_service.py` — Funcion `get_soil_data(lat, lng)` que consulta ISRIC REST API
- `backend/app/api/soil.py` — Endpoint `GET /soil/data`

### Archivos modificados

- `backend/app/schemas/analisis.py` — Nuevo schema `SoilGridsResponse`
- `backend/app/api/router.py` — Registrado `soil.router`
- `src/shared/services/api.js` — Nueva funcion `getSoilData(lat, lng)`
- `src/features/analysis/hooks/useAnalisisCultivos.js` — `handleMapChange` ahora llama a SoilGrids al hacer clic en el mapa

### Flujo

Usuario hace clic en mapa -> handleMapChange -> GET /soil/data?lat=X&lng=Y -> ISRIC SoilGrids v2.0 -> ph (phh2o), MO (soc x 1.724 / 10), textura (triangulo USDA) -> autocompleta formulario -> toast informativo

---

## 2. Random Forest en Produccion

### Archivos creados

- `backend/app/ml/inference.py` — Modulo de inferencia: carga lazy del modelo RF, funcion `predict_crop_recommendations()` con fallback automatico al heuristico

### Archivos modificados

- `backend/app/services/recommendation.py` — Usa `predict_crop_recommendations()` en vez de `CropClassifier.score()` directo
- `backend/app/services/prediction_service.py` — Reemplazado por inference + fuente indica metodo usado
- `backend/app/schemas/analisis.py` — `RecomendacionCultivo` ahora tiene `metodo` y `probabilidad`
- `backend/app/schemas/predict.py` — `CropScore` ahora tiene `metodo` y `probabilidad`

### Modelo

RandomForestClassifier(n_estimators=200, max_depth=12)

- Accuracy: 62.5%, CV: 62.35% seg 2.38%
- Features: temperatura, humedad, precipitacion, ph_suelo, materia_organica, ndvi
- Archivos: `crop_model_rf.joblib` + `crop_scaler.joblib`

## 3. Migracion DB a Local

### Archivos modificados

- `docker-compose.yml` — Nuevo servicio `db` con `postgis/postgis:16-3.4`, healthcheck, seeds automatizados
- `.env` — DATABASE_URL cambiado de Supabase a localhost:5432

### Uso de memoria Supabase

indices_satelitales: 450 MB | Total: 469 MB / 500 MB (93.8% lleno)

### Que se queda en Supabase

Solo Auth — SUPABASE_URL y SUPABASE_ANON_KEY permanecen
